# Project Logs

This directory contains structured logs extracted from TODO.md to keep it focused on current work.

## Log Files

### 📋 [AGENT_ACTIVITY_LOG.md](./AGENT_ACTIVITY_LOG.md)
**Purpose:** Historical record of completed agent work  
**Contents:**
- Daily agent activities and accomplishments
- File organization phases
- Validation and testing results
- Infrastructure checks
- Summary statistics

**When to Update:** After completing significant work phases

---

### 🚧 [FRICTION_LOG.md](./FRICTION_LOG.md)
**Purpose:** Document blockers, issues, and workarounds  
**Contents:**
- Active blockers and their status
- Resolved issues and solutions
- Patterns and learnings
- Friction metrics

**When to Update:** When encountering or resolving blockers

---

### 🎯 [DECISION_LOG.md](./DECISION_LOG.md)
**Purpose:** Record technical decisions and rationale  
**Contents:**
- Infrastructure decisions
- Repository organization choices
- Testing strategies
- Development workflow patterns
- Future decisions needed

**When to Update:** When making architectural or technical decisions

---

### 🤝 [COORDINATION_LOG.md](./COORDINATION_LOG.md)
**Purpose:** Multi-agent coordination successes and learnings  
**Contents:**
- Coordination protocol
- Success stories
- Coordination patterns
- Anti-patterns to avoid
- Metrics and improvements

**When to Update:** After successful coordination or when learning new patterns

---

## Usage Guidelines

### For Developers
- **Check these logs** when encountering similar issues
- **Reference decisions** when making related choices
- **Learn from patterns** documented in coordination log
- **Add to friction log** when you hit blockers

### For Agents
- **Extract history** from TODO.md regularly (when it exceeds ~500 lines)
- **Document decisions** as you make them
- **Record blockers** immediately when encountered
- **Update coordination log** after successful multi-agent work

### For Project Managers
- **Review activity log** for progress tracking
- **Check friction log** for systemic issues
- **Monitor coordination metrics** for team efficiency
- **Reference decision log** for architectural context

---

## Maintenance

**Frequency:** Logs should be updated as events occur  
**Archival:** Consider archiving entries older than 3 months to separate files  
**Format:** Markdown with clear sections and timestamps  
**Ownership:** All team members can contribute
