ROOT CAUSE ANALYSIS
================================================================================

The postgresql-complete.cpio.gz initramfs has THREE fundamental problems:

1. WRONG KERNEL OR MISSING MODULES
   The linux-kernel-arm64 (5.15.0-161-generic) either:
   a) Doesn't have virtio_net built-in, OR
   b) Requires virtio_net.ko module that isn't in initramfs
   
   Solution: Use a kernel with built-in virtio_net OR include virtio modules

2. INCOMPLETE ALPINE LINUX USERSPACE
   The initramfs is missing critical Alpine Linux packages:
   - shadow package (provides su command)
   - coreutils package (provides cut command)
   - Or use BusyBox equivalents properly configured
   
   Solution: Rebuild initramfs with complete Alpine base system

3. BUSYBOX COMPATIBILITY
   Init scripts use GNU grep features (-P for Perl regex)
   BusyBox grep doesn't support these features
   
   Solution: Rewrite init scripts to use POSIX-compatible regex

CRITICAL FINDING:

The build script creates an Alpine Linux-based initramfs but does NOT:
- Extract kernel modules from the Ubuntu kernel
- Include virtio_net.ko or virtio_pci.ko modules
- Configure modprobe or module loading in init script

The script assumes virtio drivers are built-in to the kernel, but:
- Ubuntu kernels typically have virtio as modules (virtio_net.ko)
- Alpine-based initramfs needs these modules explicitly included
- Without modules, eth0 interface never appears

COMPARISON WITH SUCCESSFUL VMs:

The Valkey build script has the same issue but somehow worked. This suggests:
1. Different kernel was used (with built-in virtio), OR
2. Valkey VM actually has the same network problem (untested), OR  
3. Previous manual intervention fixed the Valkey initramfs

REQUIRED FIX:

The build script needs a new section after Alpine package extraction:

```bash
# Extract kernel modules
section "Extracting Kernel Modules"
log "Extracting virtio network drivers from kernel..."

KERNEL_VERSION="5.15.0-161-generic"  # Match linux-kernel-arm64
MODULES_DIR="$WORK_DIR/rootfs/lib/modules/$KERNEL_VERSION/kernel/drivers"

mkdir -p "$MODULES_DIR/net/virtio"
mkdir -p "$MODULES_DIR/virtio"

# Extract from Ubuntu kernel package or pre-built modules archive
# Copy virtio_net.ko, virtio_pci.ko, virtio_ring.ko, etc.
# Run depmod to generate modules.dep

log "Configuring module auto-loading..."
cat >> "$WORK_DIR/rootfs/init" << 'SCRIPT'
# Load virtio modules before network configuration
modprobe virtio_pci
modprobe virtio_net
SCRIPT
```

ALTERNATIVE SOLUTIONS:

1. Use a custom-built kernel with built-in virtio drivers
2. Use Alpine's own kernel package (which has built-in virtio)
3. Switch to a different base OS (Debian netboot has virtio built-in)
