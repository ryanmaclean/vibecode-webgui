CALL STACK COMPARISON
======================

  → createVMConfiguration()
      → networkingStrategy.configure()        [Sets Device A]
      → configureStandardDevices()           [OVERWRITES with Device B]
  → VZVirtualMachine.start()
  → onVMStarted()
      → networkingStrategy.setupConnectivity()
          → startProxyServer()
              → vm.socketDevices              [Empty or wrong device]
              → ❌ FAILS


AFTER (Fixed):
--------------
startVM()
  → createVMConfiguration()
      → networkingStrategy.configure()        [Sets Device A - AUTHORITATIVE]
      → configureStandardDevices()           [Only sets generic devices]
  → VZVirtualMachine.start()
  → onVMStarted()
      → networkingStrategy.setupConnectivity()
          → startProxyServer()
              → Wait 500ms                    [Device initialization]
              → vm.socketDevices              [Device A present!]
              → Create proxy                  [Success]
              → Start proxy                   [Success]
              → ✅ WORKS



KEY INSIGHTS
============

1. ORDER MATTERS
   When multiple pieces of code set config.socketDevices, the LAST one wins
   Since BaseVMManager ran after NATNetworkStrategy, it was overwriting the
   socket device configuration.

2. TIMING MATTERS
   Even with correct device, vm.socketDevices may be empty immediately after
   VM.start() completes. Need delay for internal initialization.

3. SINGLE RESPONSIBILITY
   Socket/network devices should ONLY be configured by NetworkingStrategy
   BaseVMManager should ONLY configure generic devices (entropy, platform)

4. WEAK REFERENCES
   The delay closure captures weak references to prevent retain cycles

DEBUGGING TIPS
==============

If Test Still Fails:
--------------------

1. Check Console.app:
   $ open /Applications/Utilities/Console.app
   Filter: "NATNetworkStrategy" or "VsockProxyServer"
   Look for error messages

2. Check if VM is running:
   $ ps aux | grep BasicVibeCode

3. Check port binding:
   $ lsof -i :3000 -P -n

4. Check for port conflicts:
   $ lsof -i :3000 -P -n | grep -v BasicVibeCode

5. Verify socket device in config:
   Add NSLog in configure():
   NSLog("Socket devices configured: \(config.socketDevices.count)")

6. Verify socket device at runtime:
   Add NSLog in startProxyServer():
   NSLog("Runtime socket devices: \(vm.socketDevices.count)")

7. Increase delay if needed:
   Change: .now() + 0.5
   To:     .now() + 1.0


Common Issues:
--------------

Issue: Port already in use
Fix:   $ lsof -i :3000 -P -n | awk 'NR>1 {print $2}' | xargs kill -9

Issue: VM not starting
Fix:   Check Console.app for kernel/initramfs errors

Issue: Delay too short
Fix:   Increase delay from 0.5 to 1.0 seconds

Issue: Wrong device type
Fix:   Verify cast to VZVirtioSocketDevice succeeds
