OVERVIEW
--------
VibeCode is a comprehensive development environment that runs 5 essential 
services in a single, lightweight macOS application using Apple Virtualization 
Framework with Alpine Linux.

VERSION INFORMATION
-------------------
Version:        3.3.0
Release Date:   January 14, 2026
Build Type:     Signed Release (Apple Development Certificate)
Architecture:   Apple Silicon (ARM64)
macOS Version:  macOS 12.0+ required

SYSTEM REQUIREMENTS
-------------------
- macOS 12.0 (Monterey) or later
- Apple Silicon (M1/M2/M3/M4) processor
- 4GB RAM minimum (8GB+ recommended)
- 1GB free disk space
- Internet connection (for initial service downloads)

WHAT'S INCLUDED
---------------
VibeCode provides the following services running in an optimized VM:

1. SSH Server (Port 2222)
   - Secure shell access to the VM
   - User: root (no password required for localhost)
   
2. Valkey (Redis-compatible) (Port 6379)
   - High-performance key-value store
   - Redis-compatible protocol
   - Persistent data storage
   
3. PostgreSQL 16 (Port 5432)
   - Enterprise-grade relational database
   - Database: postgres
   - User: postgres (no password required)
   
4. OpenVSCode Server (Port 3000)
   - Full VS Code in your browser
   - Access at: http://localhost:3000
   
5. Docker Engine (Socket: unix:///var/run/docker.sock)
   - Container runtime via SSH
   - Access: ssh -p 2222 root@localhost docker ps

ADDITIONAL FEATURES
-------------------
- Datadog Monitoring Extension (included)
- Automatic service startup and management
- Persistent data across restarts
- Low resource usage (optimized Alpine Linux)
- Menu bar integration with status indicators

INSTALLATION INSTRUCTIONS
--------------------------
1. Double-click VibeCode-v3.3.0.dmg to mount the disk image

2. Drag UnifiedServicesVibeCodeApp.app to the Applications folder

3. Eject the VibeCode v3.3.0 disk image

4. Open Applications folder and launch UnifiedServicesVibeCodeApp

5. Grant necessary permissions when prompted:
   - Full Disk Access (for VM creation)
   - Network Access (for service ports)

6. First launch may take 2-3 minutes to:
   - Create VM directory structure
   - Initialize services
   - Download service containers (if needed)

QUICK START GUIDE
-----------------
After launching VibeCode, services are available immediately:

Test SSH:
  ssh -p 2222 root@localhost

Test Valkey (Redis):
  redis-cli -p 6379 PING

Test PostgreSQL:
  psql -h localhost -p 5432 -U postgres -d postgres

Open VS Code:
  Open browser to http://localhost:3000

Test Docker:
  ssh -p 2222 root@localhost docker ps

NETWORK PORTS USED
------------------
Port 2222  - SSH Server (maps to VM port 22)
Port 3000  - OpenVSCode Server (maps to VM port 3000)
Port 5432  - PostgreSQL (maps to VM port 5432)
Port 6379  - Valkey/Redis (maps to VM port 6379)

All services are bound to localhost (127.0.0.1) for security.

DATA PERSISTENCE
----------------
Service data is stored in:
  ~/Library/Containers/com.vibecode.UnifiedServicesVibeCode/Data/vm/

Data persists across:
- Application restarts
- System reboots
- Application updates

To reset all data:
- Quit the application
- Delete the vm directory above
- Restart the application

VM SPECIFICATIONS

CPU Cores:         2 cores (configurable)

Boot Time:         15-30 seconds typical

TROUBLESHOOTING
---------------
Services not starting?
  - Check system permissions (Full Disk Access)
  - Ensure ports 2222, 3000, 5432, 6379 are not in use
  - Check Console.app for detailed error logs

Port conflicts?
  - Stop other services using the same ports
  - Or use SSH tunneling to access on different ports

VM won't boot?
  - Delete ~/Library/Containers/com.vibecode.UnifiedServicesVibeCode/Data/vm/
  - Restart the application

Connection refused?
  - Wait 30-60 seconds after launch for services to initialize
  - Check menu bar icon for service status

UNINSTALLATION
--------------
To completely remove VibeCode:

1. Quit the application
2. Delete from Applications folder
3. Remove data (optional):
   rm -rf ~/Library/Containers/com.vibecode.UnifiedServicesVibeCode/

SECURITY NOTES
--------------
- All services bind to localhost only (not exposed to network)
- SSH allows root access without password (localhost only)
- PostgreSQL allows connections without password (localhost only)
- For production use, configure proper authentication
