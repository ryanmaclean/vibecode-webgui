  - Network interfaces in VM: Only lo (loopback)
  - eth0: Does not exist
  - OpenVSCode: Only accessible on 127.0.0.1 inside VM

  - Host access: Can reach VM via localhost:3000 (NAT forwarding)

NETWORK FLOW (After Fix)
================================================================================

1. Host creates VZNATNetworkDeviceAttachment
   └─→ Virtualization.framework exposes VirtIO-Net device to guest

2. Guest kernel (vmlinuz-virt) has virtio-net driver
   └─→ Driver detects VirtIO-Net device during boot

3. Driver creates eth0 network interface
   └─→ Init script detects eth0 and brings it up

4. DHCP assigns IP address (192.168.127.x)
   └─→ eth0 now has network connectivity

5. NAT bridge connects VM network to host
   └─→ Port 3000 in VM forwarded to port 3000 on host

6. OpenVSCode binds to 0.0.0.0:3000
   └─→ Accessible from both inside VM and from host

7. Host can access service
   └─→ curl http://localhost:3000 works!

WHY VIRTIO-NET IS REQUIRED
================================================================================

VirtIO is a standardized I/O framework for virtual machines:

┌──────────────────────────────────────────────────────────────┐
│ Hypervisor (Virtualization.framework)                        │
│   Provides: VirtIO devices (network, disk, console, etc.)    │
└────────────────────────┬─────────────────────────────────────┘
                         │ VirtIO Protocol
                         ▼
┌──────────────────────────────────────────────────────────────┐
│ Guest OS (Linux)                                              │
│   Requires: VirtIO drivers to use these devices              │
│                                                               │
│   Without virtio-net driver:                                 │
│     - Hypervisor provides device ✓                           │
│     - Guest cannot detect it ✗                               │
│     - No network interface created ✗                         │
│                                                               │
│   With virtio-net driver:                                    │
│     - Hypervisor provides device ✓                           │
│     - Guest detects and initializes ✓                        │
│     - Network interface eth0 created ✓                       │
└──────────────────────────────────────────────────────────────┘

Think of it like USB:
  - Host: Provides USB ports (VirtIO devices)
  - Guest: Needs USB drivers (VirtIO drivers)
  - Without driver: Device present but unusable
