## Known Limitations (Documented)

### Terminal Command Availability

**Issue**: The `ls` command does not work in the OpenVSCode integrated terminal.

**Details**:
- Terminal opens correctly ✅
- Terminal colors are configured (black/green) ✅
- Built-in commands work (`pwd`, `cd`, `echo`) ✅
- External commands fail (`ls`, `cat`, `grep`) ❌

**Root Cause**:
The OpenVSCode PTY (pseudo-terminal) environment doesn't include `/bin` in the PATH variable, even though:
- SSH terminal works perfectly
- `/bin/ls` exists and functions via SSH
- PATH is set in `/etc/profile`

**Workaround**:
Users can use SSH to access a fully-functional terminal:
```bash
ssh -p 2222 root@localhost
# Password: vibecode
# All commands work in SSH session
```

**Future Fix**:
The PATH environment variable needs to be explicitly set in the OpenVSCode terminal profile configuration. Attempts to fix this caused OpenVSCode instability and were reverted to maintain a working release.

### GitHub Actions Support
Tests can be automated but require:
- macOS runner (for Apple Virtualization.framework)
- Extended timeout (services take 30s to start)
- Port availability checks before testing

Recommended CI/CD workflow:
```yaml
name: Test VibeCode
on: [push, pull_request]
jobs:
  test:
    runs-on: macos-latest
    steps:
      - uses: actions/checkout@v4
      - name: Launch App
        run: open Apps/UnifiedServicesVibeCodeApp.app
      - name: Wait for Services
        run: sleep 30
      - name: Verify Ports
        run: |
          nc -zv localhost 2222
          nc -zv localhost 8080
      - name: Run Tests
        run: cd azure/SwiftUI-Apps && npx playwright test
```
