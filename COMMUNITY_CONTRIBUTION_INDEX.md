## How to Get Started

### I Want to...

#### ...Learn about the project
1. Read [README.md](README.md)
2. Check [ROADMAP.md](ROADMAP.md) for vision
3. Review [docs/architecture.md](docs/architecture.md)

#### ...Use VibeCode
1. Follow [QUICK-START.md](QUICK-START.md)
2. Read [UNIFIED-TOOL-GUIDE.md](UNIFIED-TOOL-GUIDE.md)
3. Check [docs/troubleshooting.md](docs/troubleshooting.md) if needed

#### ...Contribute Code
1. Read [CONTRIBUTORS_GUIDE.md](CONTRIBUTORS_GUIDE.md) (5-30 min)
2. Review [CONTRIBUTING.md](CONTRIBUTING.md) (complete process)
3. Setup dev environment with [DEVELOPMENT.md](DEVELOPMENT.md)
4. Find a [good first issue](https://github.com/yourusername/vibecode-vm/issues?q=label:%22good+first+issue%22)
5. Submit a PR using [.github/PULL_REQUEST_TEMPLATE.md](.github/PULL_REQUEST_TEMPLATE.md)

#### ...Improve Documentation
1. Read [CONTRIBUTORS_GUIDE.md](CONTRIBUTORS_GUIDE.md) (quick start)
2. Edit the relevant markdown file
3. Commit with message like: `docs: clarify X`
4. Submit PR with documentation changes section filled out

#### ...Report a Bug
1. Search [existing issues](https://github.com/yourusername/vibecode-vm/issues)
2. Open a [new issue](https://github.com/yourusername/vibecode-vm/issues/new)
3. Use [bug_report.md](.github/ISSUE_TEMPLATE/bug_report.md) template
4. Include environment details and reproduction steps

#### ...Suggest a Feature
1. Check [ROADMAP.md](ROADMAP.md) first
2. Search [existing discussions](https://github.com/yourusername/vibecode-vm/discussions)
3. Start a [discussion](https://github.com/yourusername/vibecode-vm/discussions) or open [feature request](.github/ISSUE_TEMPLATE/feature_request.md)
4. Describe problem, solution, and use cases

#### ...Ask a Question
1. Search [discussions](https://github.com/yourusername/vibecode-vm/discussions)
2. Check [docs/troubleshooting.md](docs/troubleshooting.md)
3. Start a [discussion thread](https://github.com/yourusername/vibecode-vm/discussions/new)
4. Or ask in [issue template: question](.github/ISSUE_TEMPLATE/question.md)

#### ...Report a Security Issue
**DO NOT** create a public issue!

1. Email security@vibecode.dev with details
2. Or use [GitHub Security Advisory](https://github.com/vibecode/webgui/security/advisories)
3. Include: description, impact, reproduction steps, suggested fix
4. We'll respond within 48 hours

## Types of Contributions Welcomed

- **Code**: Features, bug fixes, optimizations, tests
- **Documentation**: Guides, tutorials, examples, clarifications
- **Testing**: Bug reports, testing features, performance analysis
- **Design**: UI/UX suggestions, icons, diagrams, mockups
- **Community**: Answering questions, mentoring, discussions

## Community Standards

All participants must follow the [Code of Conduct](CODE_OF_CONDUCT.md):
- Be respectful and inclusive
- Assume good intent
- Focus on constructive feedback
- Celebrate diverse perspectives

Violations should be reported to conduct@vibecode.dev.

## Templates at a Glance

### Creating an Issue

The appropriate template will be suggested based on context:

1. **Bug Fix** - Use [bug_report.md](.github/ISSUE_TEMPLATE/bug_report.md)
   - Environment, steps to reproduce, expected vs actual
   - Include logs and screenshots
   - Mark severity/impact

2. **Feature Request** - Use [feature_request.md](.github/ISSUE_TEMPLATE/feature_request.md)
   - Problem statement, proposed solution, use cases
   - Compatibility and complexity assessment
   - Priority level

3. **Code Improvement** - Use [improvement.md](.github/ISSUE_TEMPLATE/improvement.md)
   - Current approach, problems, proposed improvements
   - Benefits, effort estimation

4. **Question** - Use [question.md](.github/ISSUE_TEMPLATE/question.md)
   - Better for GitHub Discussions
   - Provide context and what you've tried

### Creating a Pull Request

Use [PULL_REQUEST_TEMPLATE.md](.github/PULL_REQUEST_TEMPLATE.md):

- Clear description of changes
- Related issues
- Type of change
- Testing done
- Detailed checklist
- Breaking changes if applicable
